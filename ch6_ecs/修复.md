# ch6_ecs 修复记录

---

## 1. 测试断言被 table 引用语义绕过

**现象**：`L10 tick moves position` 报 `11.0 → 11.0`，断言 `after.x - before.x == 1` 失败。

**原因**：

```lua
local before = w2:get(1, "position")   -- 返回 component table 的引用
w2:tick(1.0, 1000)
local after  = w2:get(1, "position")   -- 同一个 table
check(..., math.abs(after.x - before.x - 1.0) < 1e-6, ...)
```

`get()` 返回的是**引用**，`before` 和 `after` 指向同一张表。
tick 之后 `before.x` 也变成了新值，差值恒为 0。
更隐蔽的是：即使断言写成"应该相等"也会通过——**引用语义会让断言永远成立**。

**修复**：先快照标量值，再执行被测操作：

```lua
local before_x = w2:get(1, "position").x
w2:tick(1.0, 1000)
local after_x  = w2:get(1, "position").x
```

**教训**：涉及"变化前后对比"的断言，快照必须是**标量**，不能是引用。

## 2. 测试用例选错了实体（组件过滤未生效的场景）

**现象**：初版 L10 用 `e6`（只有 `position`，没有 `velocity`）测"tick 后位置移动"，
结果位置不变——因为 tick 里 `if pos and vel then` 正确地把 e6 跳过了。

**分析**：这不是实现 bug，是**测试选错了对象**。
但这个错误意外地有价值：它说明"组件过滤"确实生效了。

**修复**：改用有 `position + velocity` 的 `e1` 测移动，
并**保留 e6 作为新的断言 L10b**（"没有 velocity 的实体不应被移动"）——
把误用变成了一条正向测试。

## 4. 认知修正：`-O3` 对 SoA 遍历没有帮助

**现象**：`-O2` 与 `-O3` 编译下，C ECS 都是 1.24 ms / 1000 帧，完全一致。

**分析**：不是指令数受限，而是**内存访问模式 + 分支预测**受限：

- 1000 实体 × 8 个数组 ≈ 32 KB，在 L1 cache 边界附近
- 边界检查分支几乎不触发，预测命中率接近 100%
- 此时增加指令级优化没有收益

**处理**：Makefile 保留 `OPT ?= -O2` 并支持覆盖（`make OPT="-O3" bench`），
在 OPTIMIZATION.md 记录实验结论：**优化 SoA 遍历要靠数据布局，不是编译器开关。**

## 5. 跨语言调用的两种成本被混淆

**现象**：最初只测了"C 内部连续 tick"，得出 1.35 μs/帧。
但真实用法是"Lua 每帧调一次 `w:update()`"，两者是否等价未知。

**处理**：补了两个独立测量，结论相反：

| 操作 | 成本 | 结论 |
|---|---|---|
| 每帧一次 Lua→C 调用 | −0.041 μs（噪声内） | **可忽略**，不必为省调用做复杂设计 |
| 把 1000 个实体读回 Lua | 52.31 μs | **是一帧的 39 倍**，必须避免 |

**教训**："跨语言开销"不是一个数，要区分**调用次数**和**数据量**。
前者便宜，后者昂贵。
