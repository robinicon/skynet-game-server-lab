## 二、必须先修的口径冲突：客户端到底热不热代码

这是 v2 相对 v1 最重要的一处纠正。同一工程内存在两个相反结论：

| 出处 | 说法 | 时间 |
|---|---|---|
| `legend3D/README.md` 第 3 行 | "客户端 Unity 2021.3 + **HybridCLR + xLua**"，阶段 3 写"客户端**双热更**" | 较早 |
| `docs/三端重制排程/01_三端架构与技术选型.md` §1 结论摘要 | "客户端热更：**不做代码热更**，只做资源热更"，理由：iOS 审核 2.5.2、小游戏无 JIT/动态程序集 | 2026-11-06 |
| `docs/三端重制排程/03_风险与决策清单.md` C8 | "客户端代码热更（HybridCLR/xLua）与 iOS/小游戏约束冲突 → **新约束：不做代码热更**" | 2026-11-06 |

**判定：以 01/03 的定案为准（较新、有决策理由、有风险编号），README 是过时口径。**

**处置（写文章前必须先做）**：

1. 修订 `legend3D/README.md` 的技术栈描述，与 01 定案对齐——否则每篇文章都要替 README 解释一次，读者必然混乱。
2. v2 全部篇目统一表述为：**只做资源热更**；代码逻辑缺陷走发版。
3. 保留一段"为什么曾经想上双热更"的说明（这才是真实工程决策），但不写成推荐方案。

> 这一条本身就是一篇好文章（U09）。工业级项目的典型病灶不是"选错技术"，而是**同一份工程里两个相反的定案并存，且新来的人先读到的是旧的那个**。

## 四、工业级七条判据（每篇自检）

1. **有交付物**：读完能拿到脚本、清单、预算表或评审记录中的至少一件。
2. **有版本门**：明确该篇服务于哪个版本门（V0.1–V1.0），不写"纯知识科普"。
3. **有预算**：凡涉及性能/体积，必须给出目标值与测量方法，不写"优化了很多"。
4. **有失败路径**：登录、发布、热更、AI 调用都要写失败分支，不只写成功路径。
5. **有合规位**：三端发布必带备案/实名/隐私/权限，不只写"点构建"。
6. **有回滚**：发布与热更必须写回滚动作与时限。
7. **有边界**：蓝本未公开、未实机验证、未排期的，必须当场说清。

#### U02 · [Unity 手记] 一个打包脚本把 AB variant 当平台后缀：资源热更的第一块地基

**档位** A ｜ **版本门** V0.1 ｜ **交付物** 打包预算校验脚本（自写）

**开篇钩子**：`assetBundleVariant` 本来是给 `hd`/`sd` 资源变体用的。这个脚本把它设成了 `"win"`/`"android"`——能跑，但语义被挪用。

**章节**：
1. 那一行 `importer.assetBundleVariant = ext` 的用意

**开篇钩子**：上线日期不是"做完那天"。它是 `max(团队完工周, 备案下证周 + 2 周)`——这两个日期必须分开汇报。

**章节**：
1. 版本门禁：client / config / resource 三版本校验，不符返回强更，不静默进服
2. 崩溃上报与日志回传：能定位到版本/设备/场景
3. 灰度：单区灰度 10%→100%，回滚 <5 min
4. 压测口径：3000 CCU、p99 <50 ms（设计目标，非实测普遍结论）
5. 合规外部轨道：版号/备案典型 3–6 个月；**备案未下 V1.0 不可发布**，可先出包/内测/灰度
6. 上线检查单：DB 备份、监控、告警、容量，每项有责任人与验证命令
7. 首日值班：应急预案、客服话术、热修走 Lua reload
8. 复盘 3 条
9. 已知环境限制：排程口径，非本项目上线记录
10. 代码与运行：门禁脚本用法 + 回滚手册目录

**配图**：封面 + 上线门禁/灰度流程图 ｜ **数据说明**：数字来自 `02` V0.7/§8

**系列小结（非预告）**：
16 篇按"基线 → 链路 → 预算 → AI → 三端"排下来，真正反复出现的只有一件事：**先定边界，再写代码**。边界包括版本边界（只做资源热更）、体积边界（4 MB）、平台边界（只能 WSS）、时间边界（备案 3–6 个月）。边界一旦写错，后面每篇都在还债。

## 十一、红线：不许编

1. **不许编客户端类名/方法名**。蓝本没有的，写"设计上应有"并给自写示例。
2. **不许编性能数字**。没有实测只写定性；工程定案数字必须标"定案/待复核"。
3. **不许把推断写成事实**。U03 的运行时加载、U07 的 prefab 装配、三端首屏时间，均标"待验证"。
4. **不许把服务端行为安到客户端头上**，两端分开写。
5. **不许省略免责句**。B/C 档正文首次出现实现描述时必须写"蓝本未公开该层"或"非本项目实测"。
6. **不许把 AI 方法笔记包装成项目成果**。U11 必带"无配套工程与实测数据"。
7. **不许把限额写成永久值**。小游戏 4 MB / 20 MB、targetSdk，一律标"以当年公告为准，W1 复核"。
