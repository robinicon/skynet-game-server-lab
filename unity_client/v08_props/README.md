# v08_props · 泳道编解码与槽位分配

**对应篇目**：V08《进服与属性同步》｜**档位**：B 档

## 解决什么

属性同步的三条硬规则：只要变化的槽位、布尔集合用 `bits`、槽位号有语义不能乱用。
这里把它们做成可执行的编解码与**槽位冲突检测**。

## 文件

| 文件 | 作用 |
|---|---|
| `props.py` | 槽位分段、`PropValue` 三通道互斥、增量 diff/合并、bits 打包、冲突检测 |
| `test_props.py` | 29 条断言：槽位、冲突、通道、增量、bits |

## 跑

```bash
python unity_client/v08_props/test_props.py
```

## 新增发现（台账 C-46）

**示例槽位表本身有重叠。** `quest.progress = 3000 + (qid & 0xFF)`，当 `qid = 100` 时
落在 **3100** —— 正好是 `quest.done` 的固定槽位。工具检出：

```
[(3100, 'quest.done(bits)', 'quest.progress(qid=100)')]
```

修正建议：把活跃任务数限制在 64（`mask=0x3F`），`progress` 占 `3001~3063`，`done` 用 `3100`。
`active_qids` 超过容量时必然回绕重叠 —— **容量是硬约束，不是建议**。

## 为什么 bits 值得单独一条

20 个任务的完成态：
- 用 `num=1` 逐条发 → 20 条 `PropValue`
- 用 `bits` → 1 条，64 个位

增量时只发变化的位。这条不是"优化技巧"，是同步带宽的基本盘。

## 证据边界

槽位号是**本文按模块分段编的示例**，仓库里没有 `share_data` 字段表。落地前必须与
客户端字段定义表逐条对齐，否则会出现"slot 1001 服务端是金币、客户端是钻石"。
