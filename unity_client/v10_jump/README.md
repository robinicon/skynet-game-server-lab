# v10_jump · 跨节点跳转窗口期

**对应篇目**：V10《跨节点跳转窗口期》｜**档位**：B 档

## 解决什么

服务端跳转有个窗口期，期间消息缓存重放。客户端在这段时间继续发操作，要么被丢、要么重放两次。
本目录复刻 `ch11_jump/service/gate_redirect.lua` 的路由表语义，并补上正文指出的两个缺口（C-32）。

## 文件

| 文件 | 作用 |
|---|---|
| `jump.py` | fd→agent 路由表、窗口开关、缓存重放、回滚、超时、溢出、request_id 去重 |
| `test_jump.py` | 31 条断言：缓存、重放顺序、回滚、超时、溢出、去重窗口 |

## 跑

```bash
python unity_client/v10_jump/test_jump.py
```

## 六条不变量

1. 窗口期消息进 buffer，**不投递**
2. `rebind` 必须**先建新表再重放** —— 重放走 `route` 时 `window` 已为 False，不会再进 buffer
3. 失败**必须回滚**，否则 fd 卡在 `window=true`，后续消息全堆在 buffer，玩家表现为"卡死"
4. 窗口要有**超时**（建议 10s），否则 `rebind` 不到达就永久挂起（C-32）
5. buffer 要有**上限**（建议 256），溢出丢最旧并计数（C-32）
6. 重放要按 `request_id` **去重**，滑动窗口 256 条（C-15）

## 为什么第 2 条最容易写错

顺手写成"先重放、再建表"，重放的消息会在 `window=true` 的旧表上再进一次 buffer，
造成无限循环 —— 而且日志上看起来"消息都有了"。测试 `test_rebind_order` 专门守这条。

## 客户端侧的责任

服务端能保证"消息不丢"，但"消息不重复执行"要客户端与服务端共同保证：
**锁输入 + 过场遮罩 + 超时出口**，三件事必须在"不知道要等多久"的前提下都成立。
超时不要自动重试 —— 跳转不是幂等的，自动重试会建出两个 agent。
