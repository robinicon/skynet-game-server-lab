# ch8_components 修复记录

---

## 1. `function M.handlers["bag.add"](ctx)` 是非法语法

**现象**：三个组件全部加载失败，日志显示

```
[agent] component bag not found: error loading module 'shared.component_bag'
  from file './shared/component_bag.lua':
	./shared/component_bag.lua:31: '(' expected near '['
```

**原因**：Lua 的 function 定义语法里，函数名只支持**点号分隔的标识符**：
`function a.b.c(args)` 合法，但 `function a["b.c"](args)` 不合法——
`['` 让解析器以为还在写函数名。

**修复**：改成赋值形式：

```lua
-- ❌
function M.handlers["bag.add"](ctx, item_id, count) ... end
-- ✅
M.handlers["bag.add"] = function(ctx, item_id, count) ... end
```

**注意区分**：`M.handlers["quest.complete"](ctx, id)` 这种**调用**是合法的，
只有**定义**受限。同一个文件里两种写法都有，容易改漏。

## 2. 组件 init 失败后没有回滚，残留在加载顺序里

**现象**：B3.3 断言 `#core:list() == 0` 失败，列表里残留 `broken`。

**原因**：`Core:load` 先把组件写进 `comps` 和 `order`，再调 `init`。
init 抛错时直接 return false，但没有把已写入的登记撤销：

```lua
self.comps[name] = mod
self.order[#self.order + 1] = name
if not ok then
    return false, "init failed"     -- ← comps / order 里的条目没清掉
end
```

**后果**：
- `list()` 里出现一个从未成功初始化的组件
- 后续 `shutdown()` 会对它调用 shutdown（半初始化状态，行为未定义）
- 上层若只检查 `comps[name] ~= nil` 会误判为"已加载"

**修复**：init 失败时完整回滚（comps / order / msg_count）。

**教训**：**"先登记再初始化"的顺序必须配"失败回滚"**。
另一种更简洁的做法是"先初始化再登记"，但那样 init 里就无法访问 core 自身的引用。

## 3. dispatch 的 pcall 只拿到第一个返回值（预判修复）

**风险**：handler 通常返回 `(code, data)`，而

```lua
local ok, res = pcall(r.fn, self.ctx, ...)
return res          -- 只拿到 code，data 丢失
```

这是与 ch4 `修复.md` #8 同源的坑（`pcall` 只取首个返回值）。

**修复**：用 `table.pack` + `table.unpack` 保留全部返回值：

```lua
local p = table.pack(pcall(r.fn, self.ctx, ...))
if not p[1] then return error_code.ERR_INTERNAL, tostring(p[2]) end
if p.n == 1 then return error_code.OK end
return table.unpack(p, 2, p.n)
```
